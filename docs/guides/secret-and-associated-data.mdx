Antech supports two optional advanced inputs on the **same** canonical construction. They are not separate algorithms and do not make password hashing “more secure” by themselves — they change the threat model.

## Application secret (key)

- Confidential bytes held by the application (or HSM / KMS), **never** written into `$antech$v2$…`
- Bound into the seed; changing the secret changes the digest
- Empty secret (`Some([])`) is distinct from no secret (`None`)
- Stored hashes only record a public marker `sk=1` when a secret was used
- Plain `verify` on a secret-bound hash returns `MissingSecret` (fail closed)

**Threat model:** an offline dump of password hashes alone is not enough to verify guesses without also obtaining the application secret. It does **not** replace password strength, rate limiting, or secret storage hygiene. Losing the secret makes legitimate verification impossible.

## Associated data (AD)

- Public contextual bytes (tenant id, user id, realm, …) supplied by the application
- **Not** a password secret; do not treat AD as confidential storage
- Bound into the seed; changing AD changes the digest
- Empty AD is distinct from no AD
- Stored hashes only record `adl=<n>` (length); AD bytes are **not** serialized
- Caller must supply the same AD at verify time

**Threat model:** binds hashes to application context so a stolen hash string is less portable across tenants/contexts when the verifier always supplies AD. It is not encryption of the password.

## API shape

Keep the simple path unchanged:

- `hash(password)` / `verify(password, stored)` / `needs_rehash(stored)`

Advanced (conceptual):

- `hash_with_inputs(password, config, inputs)`
- `verify_with_inputs(password, stored, inputs)`
- `hash_with_inputs_and_salt(…)` for KATs

`needs_rehash` may prefer hashes that record `sk=1` / `adl=` via policy flags; it never compares secret bytes.

## Limits

| Input | Max bytes | Rationale |
|---|---|---|
| Secret | 1024 | Typical API/HMAC keys; bounds seed-input DoS |
| Associated data | 65536 | Public context; larger than secrets, still bounded |

Antech is published as experimental software. Benchmarks and SDK packaging help you integrate and compare; they do **not** replace cryptographic review.

## Intended use today

- Research and attacker-cost comparison against Argon2-class baselines
- Early product experiments behind explicit risk acceptance
- Conformance and interoperability work across language bindings

For production password storage on the public internet, **prefer Argon2id** until independent review concludes and you decide the residual risk is acceptable.

## Practices that still apply

- Store only `$antech$v2$` strings
- Never log passwords or cleartext salts
- Keep crypto in the Rust core — do not “simplify” the DAG in an application language
- Upgrade parameters only after successful verify
- Treat malformed stored hashes as operational failures, not user typos

## Threat-model reminders

| Attacker | Defender posture |
|---|---|
| Online guessing | Rate-limit and lockout still required — KDF cost alone is not enough |
| Offline dump | Memory + graph cost raise cracking expense; defaults target modest hosts |
| Implementation fork | Using a second crypto path voids conformance guarantees |

Antech KDF is **experimental** software. It has not completed independent cryptographic review. Benchmarks help compare attacker cost under fixed conditions; they do not replace cryptanalysis.

For production password storage on the public internet, **prefer Argon2id** until you have read the [Security & review](../security-review/overview) materials and accepted the residual risk.

## Intended use today

- Integration testing and interoperability across language SDKs
- Attacker-cost comparison against Argon2-class baselines
- Early experiments behind explicit, written risk acceptance

## Integration habits

- Store only `$antech$v2$` strings — never passwords or cleartext salts
- Never log passwords or derived digests in application logs
- Keep cryptography in the Rust core; do not reimplement the DAG in application code
- Upgrade parameters only after a successful `verify`
- Treat malformed stored hashes as operational failures, not user typos
- Rate-limit and lock out online guessing — KDF cost alone is not enough

## Threat-model reminders

| Attacker | Defender posture |
|---|---|
| Online guessing | Rate-limit and lockout still required |
| Offline dump | Memory + graph cost raise cracking expense; defaults target modest hosts |
| Implementation fork | A second crypto path voids conformance guarantees |

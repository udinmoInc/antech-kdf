```rust
let ok = antech_kdf::verify(password, &stored)?;
```

`verify` parses the string, rebuilds config, re-derives with the embedded salt, and compares digests in constant time. Callers never need to extract salt or parameters manually.

## Outcomes

| Result | Meaning | Application action |
|---|---|---|
| `Ok(true)` | Password matches | Authenticate; optionally check rehash policy |
| `Ok(false)` | Password does not match | Reject credentials |
| `Err(_)` | Malformed string or invalid embedded parameters | Alert operators; fail closed |

On the FFI, a mismatch is typically surfaced as a dedicated verification-failed status, while parse failures are invalid-hash / format errors. Language wrappers should keep those cases distinct.

<Note>
Surface `Err` / invalid-hash as an infrastructure problem to operators. Do not tell end users “wrong password” when the stored string itself is corrupt.
</Note>

## Timing

Verification cost matches hashing cost for the stored profile. Budget login latency and concurrent capacity with the host scheduler in mind — a burst of verifies is a burst of 16 MiB (or larger) working sets.

Applications evolve memory targets over time. A rehash policy compares the parameters embedded in a stored string to your current floor and preference — without requiring a separate migration table of “algorithm versions.”

```rust
use antech_kdf::{needs_rehash, needs_rehash_with_policy, RehashPolicy};

if needs_rehash(&stored)? {
    // default policy (16 MiB targets)
}

let policy = RehashPolicy::builder()
    .minimum_memory_mib(16)
    .preferred_memory_mib(32)
    .preferred_fan_in(2)
    .preferred_output_length(32)
    .build();

if needs_rehash_with_policy(&stored, &policy)? {
    // upgrade after successful verify
}
```

A rehash is signaled when stored memory, fan-in, or output length falls below the policy targets. Graph and block size are part of the encoded string; treat changing them as a deliberate construction change, not a routine upgrade.

## Recommended login order

1. `verify` — reject on mismatch or hard error
2. `needs_rehash_with_policy` — only if verify succeeded
3. `hash_with_config` — write the new string atomically

<Tip>
Always verify successfully before spending another full derive on an upgrade.
</Tip>

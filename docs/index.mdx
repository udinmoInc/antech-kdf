Antech is a password key-derivation function for hosts that cannot dedicate large Argon2-style working sets, but still want offline attack cost that does not fall apart when defender memory is modest. The shipping profile walks a **combined-frontier** dependency graph in roughly **16 MiB**. Work is defined as `memory / block_size` — there is no separate iteration-count knob.

## Status

Antech is **experimental**. Use it for research, comparative benchmarks, and early integrations behind an explicit risk acceptance. Prefer **Argon2id** for production password storage until independent cryptanalysis is complete.

<Note>
Package metadata marks this product Experimental — not Beta. Review materials ship in the repository under `research/security-review/`.
</Note>

## How a hash is built

Password and salt bind into a seed, the engine walks the DAG, then the digest is packed into a portable string:

  D --> E["Encode antech v2"]

## Defaults worth memorizing

| Knob | Default |
|---|---|
| Memory | 16 MiB |
| Block size | 32 bytes |
| Fan-in | 2 |
| Graph | CombinedFrontier (`g=3`) |
| Salt length | 16 bytes |
| Output length | 32 bytes |

Stored form:

```text
$antech$v2$m=<kib>,s=<salt_len>,b=<block>,f=<fan>,g=<graph>,l=<out>$<salt_hex>$<digest_hex>
```

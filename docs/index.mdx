Antech KDF is a password key-derivation function built around a compute-memory construction. The default profile walks a **combined-frontier** dependency graph in roughly **16 MiB** of working memory. Work scales with `memory / block_size`; there is no separate iteration-count knob.

Stored hashes are self-describing `$antech$v2$` strings. One Rust engine implements the cryptography; language SDKs are thin wrappers over a shared C ABI.

<Warning>
Antech KDF is **experimental**. It has not completed independent cryptographic review. Prefer **Argon2id** for production password storage until you have read the review materials and accepted the residual risk.
</Warning>

## Install

**Rust** — add the crate directly:

```toml
[dependencies]
antech-kdf = "0.1"
```

Requires Rust 1.70+.

**Other languages** — install the published package for your platform, then confirm the version matches **0.1.0**:

| Language | Install | Verify version |
|---|---|---|
| Python | `pip install antech-kdf==0.1.0` | `pip show antech-kdf` |
| Node / TypeScript | `npm install antech-kdf@0.1.0` | `npm list antech-kdf` |
| .NET | `dotnet add package Antech.Kdf --version 0.1.0` | check the package reference in your project |
| Rust | `cargo add antech-kdf@0.1` | `cargo tree -p antech-kdf` |

Go, Java, Kotlin, Swift, and C/C++ packages follow the same API through the FFI. See [SDK overview](./sdk/overview) for per-language notes.

Non-Rust SDKs load a native `antech_kdf_ffi` library. If your runtime cannot find it, set `ANTECH_KDF_LIB` to the directory that contains the library for your OS.

## Hash and verify

```rust
use antech_kdf::{hash, verify, needs_rehash};

let stored = hash("correct_horse_battery_staple")?;
assert!(verify("correct_horse_battery_staple", &stored)?);
assert!(!needs_rehash(&stored)?);
```

Persist the returned string as-is. `verify` parses parameters, salt, and digest from the encoding and compares in constant time.

## Default parameters

| Parameter | Default |
|---|---|
| Memory | 16 MiB |
| Block size | 32 bytes |
| Fan-in | 2 |
| Graph | CombinedFrontier (`g=3`) |
| Salt length | 16 bytes |
| Output length | 32 bytes |

```text
$antech$v2$m=<kib>,s=<salt_len>,b=<block>,f=<fan>,g=<graph>,l=<out>$<salt_hex>$<digest_hex>
```

Custom profiles use `hash_with_config`. After a successful login, `needs_rehash_with_policy` can detect when stored parameters fall behind your policy.

## API surface

Every SDK exposes the same operations:

| Operation | Purpose |
|---|---|
| `hash` | Default 16 MiB profile with random salt |
| `hash_with_config` | Explicit structural parameters |
| `verify` | Constant-time password check |
| `needs_rehash` / `needs_rehash_with_policy` | Detect outdated stored parameters |
| `hash_with_config_and_salt` | Deterministic vectors (tests only) |

Full signatures: [API reference](./reference/api). Configuration bounds: [configuration reference](./reference/configuration-reference).

## Security & review

Antech is submitted for independent cryptanalysis. The repository ships a formal specification, production source, test vectors, conformance suite, benchmark evidence, prior attack results, and known limitations.

Reviewers and integrators should start at [Security & review](./security-review/overview). That page lists where each artifact lives and how to reproduce vectors, run conformance tests, and compare measured results with the documented construction.

For day-to-day integration habits (logging, rehash timing, rate limits), see [Security guidance](./guides/security).

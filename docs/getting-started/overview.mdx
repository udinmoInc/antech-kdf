Antech is a password KDF aimed at servers that cannot spare a large Argon2 working set, but still want attacker cost that does not collapse when memory is scarce. The production profile walks a **combined-frontier** dependency graph in about **16 MiB**. Work is `memory / block_size` — there is no separate iteration knob.

## Where things stand

Antech is **experimental**. It is useful for research, comparative benchmarks, and early integration work. It is **not** a drop-in replacement for Argon2id in production until independent cryptanalysis is complete and you have explicitly accepted the risk.

<Note>
Status in package metadata is <InlineBadge type="experimental" /> — not Beta. Review materials live under `research/security-review/` in the repository.
</Note>

## How a hash is built

Password and salt bind into a seed, the engine walks the DAG, then the digest is packed into a portable string:

## Defaults worth memorizing

| Knob | Default |
|---|---|
| Memory | 16 MiB |
| Block size | 32 bytes |
| Fan-in | 2 |
| Graph | CombinedFrontier (`g=3`) |
| Salt length | 16 bytes |
| Output length | 32 bytes |

Stored form:

```text
$antech$v2$m=<kib>,s=<salt_len>,b=<block>,f=<fan>,g=<graph>,l=<out>$<salt_hex>$<digest_hex>
```

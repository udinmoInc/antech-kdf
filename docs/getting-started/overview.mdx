Antech exists because many small services want password hashing that remains expensive for offline attackers even when the defender only has tens of mebibytes free. Traditional memory-hard designs often push toward larger footprints; Antech studies a **compute-memory** trade where the working set stays near **16 MiB** while the dependency graph tries to keep reduced-memory shortcuts incorrect or costly.

## Design choices you will feel

### Work model

There is no `t_cost`-style iteration knob. The number of nodes is `memory_bytes / block_size`. Changing memory or block size changes work directly.

### Graph

Production hashing defaults to **CombinedFrontier**. The graph kind is mixed into the seed and stored as `g=` in the encoded hash, so swapping graphs changes digests.

### Encoding

Stored values are self-describing `$antech$v2$…` strings. `verify` rebuilds configuration from the string. Legacy `v1` encodings are rejected.

### Single crypto core

Language SDKs call `antech-kdf-ffi`. They do not reimplement mixing, parenting, or finalization.

## When to use it today

| Situation | Guidance |
|---|---|
| Research / benchmarks | Fine — compare against Argon2-class baselines carefully |
| Internal experiments | Fine with risk acceptance |
| Public production auth | Prefer Argon2id until review concludes |

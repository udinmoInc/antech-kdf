Pick the path that matches how you ship: Rust-only applications link `antech-kdf` directly. Other languages load `antech-kdf-ffi` as a shared library, then use a thin wrapper.

<Prerequisites items={[
  'Rust 1.70 or newer',
  'Git checkout of udinmoInc/antech-kdf for SDK native builds'
]} />

## Rust crate

Add the public API crate to your project:

```toml
[dependencies]
antech-kdf = "0.1"
```

From a local checkout:

```bash
cargo add antech-kdf --path crates/antech-kdf
```

That is enough for servers written in Rust. You do not need the FFI library unless another language will call Antech.

## Native library for SDKs

Wrappers under `bindings/` expect a release build of the C ABI:

<FrameworkTabs frameworks={['Unix', 'Windows']}>
  <FrameworkContent framework="Unix">
    ```bash
    ./sdk/scripts/build-native.sh
    ls sdk/native/
    ```
  </FrameworkContent>
  <FrameworkContent framework="Windows">
    ```powershell
    ./sdk/scripts/build-native.ps1
    Get-ChildItem sdk\native
    ```
  </FrameworkContent>
</FrameworkTabs>

You should see the platform library (`antech_kdf_ffi.dll` / `.so` / `.dylib`) and `antech_kdf.h`.

<Tip>
If a language package cannot find the library, set `ANTECH_KDF_LIB` to the file path or to the `sdk/native` directory.
</Tip>

## Language packages

| Ecosystem | After native build |
|---|---|
| Python | `pip install -e bindings/python` |
| Node / TypeScript | `cd bindings/node && npm install && npm run build` |
| Go | cgo module in `bindings/go` |
| .NET | `dotnet build bindings/dotnet/Antech.Kdf` |
| Java | Maven project in `bindings/java` + native on the library path |

Keep versions aligned with the root `VERSION` file:

```bash
python sdk/scripts/sync-versions.py
```

## Sanity checks

```bash
cargo test -p antech-kdf
cargo test -p antech-kdf-ffi
python sdk/conformance/run_python.py
```

`AntechEngine` in `antech-kdf-core` is the only production derivation path. Language packages call into it through FFI; they must not reimplement mixing, parenting, or finalization.

## Call path

1. Validate config.
2. Acquire a host scheduler permit.
3. Derive from password, salt, and config.
4. Encode an `$antech$v2$…` string.
5. Release the permit.

## Stages inside derive

1. **Bind** — password and salt expand into a domain-separated seed.
2. **Fill** — walk the dependency graph over `memory / block_size` nodes.
3. **Finalize** — compress the terminal state into the requested output length.
4. **Encode** — pack parameters, salt, and digest into `$antech$v2$…`.

Construction version and domain-separation tags are fixed in core. Changing them silently breaks published vectors and review evidence.

## Public helpers on top of the engine

| Helper | Behavior |
|---|---|
| `hash` / `hash_with_config` | Random salt, returns encoded string |
| `hash_with_config_and_salt` | Fixed salt for KATs and interop tests |
| `verify` | Parse → derive with stored salt → constant-time compare |
| `needs_rehash*` | Compare stored parameters to a policy |

<Tip>
Use `hash_with_config_and_salt` only in tests. Production authentication should keep random salts from `hash` / `hash_with_config`.
</Tip>

## Failure modes

| Condition | Result |
|---|---|
| Config out of bounds | `InvalidConfig` before any heavy work |
| Host scheduler exhausted | Resource error; no over-commit |
| Malformed v2 string on verify | Format / config error, never a false positive match |

`AntechEngine` in `antech-kdf-core` is the only production derivation. Language packages call into it through FFI; they must not reimplement mixing or graph selection.

## Call path

<Mermaid chart={`
graph LR
  A["Validate config"] --> B["Acquire scheduler permit"]
  B --> C["derive password salt config"]
  C --> D["encode_hash"]
  D --> E["Release permit"]
`} />

## Public helpers on top of the engine

| Helper | Behavior |
|---|---|
| `hash` / `hash_with_config` | Random salt, returns encoded string |
| `hash_with_config_and_salt` | Fixed salt for KATs and interop tests |
| `verify` | Parse → derive with stored salt → constant-time compare |
| `needs_rehash*` | Compare stored parameters to a policy |

Construction version and domain-separation tags are fixed in core. Changing them silently breaks published vectors and review evidence.

<Tip>
Use `hash_with_config_and_salt` only in tests. Production authentication should keep random salts from `hash` / `hash_with_config`.
</Tip>

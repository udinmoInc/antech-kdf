Non-Rust packages load `libantech_kdf_ffi` and call symbols declared in `bindings/c/antech_kdf.h`. Wrappers stay thin: map types, free strings, and surface errors. Cryptography stays in Rust.

## Guarantees

- Entry points are thread-safe and effectively stateless for callers
- Panics at the boundary become `ANTECH_INTERNAL_ERROR`
- Hash strings are Rust-allocated; free with `antech_free`
- Prefer `*_bytes` APIs when passwords are arbitrary binary
- Empty passwords are valid when length is `0` (null pointer allowed only with zero length)

## Operation map

| C API | Rust |
|---|---|
| `antech_hash` / `_bytes` | `hash` |
| `antech_hash_with_config*` | `hash_with_config` |
| `antech_hash_with_config_and_salt` | KAT / interop helper |
| `antech_verify*` | `verify` |
| `antech_needs_rehash*` | rehash checks |
| `antech_config_default` | default `AntechConfig` POD |
| `antech_free` | free returned C strings |

## Status codes (summary)

| Code | Meaning |
|---|---|
| `0` | Success |
| negative | Mapped library errors (`INVALID_CONFIG`, format, resource, …) |

Exact enumerations are in the ABI reference. Language wrappers should preserve the mapping so conformance runners can assert identical behavior.

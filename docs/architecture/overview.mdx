Antech keeps a hard line between **production** code and **research**. SDKs and attackers both depend on core; core never depends on research. That dependency direction is intentional: experimental cryptanalysis and GPU runners cannot leak into the shipping library.

## Production crates

| Crate | Responsibility |
|---|---|
| `antech-kdf` | Public `hash` / `verify` / rehash API |
| `antech-kdf-core` | `AntechEngine`, resource scheduler |
| `antech-kdf-format` | `$antech$v2$` encode and parse |
| `antech-kdf-types` | Config, errors, graph kinds |
| `antech-kdf-ffi` | C ABI used by every non-Rust SDK |
| `antech-kdf-cli` | Command-line hash / verify |

Research lives under `research/code/` as a **separate Cargo workspace**. Production workspace members never list research crates.

## What stays out of production

Attacker models, GPU kernels, TMTO explorers, and security-review runners live under `research/`. They may depend on `antech-kdf-core` for correct digests, but they are never linked into `antech-kdf` or language SDKs.

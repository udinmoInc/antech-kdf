Production code lives under `crates/`, `bindings/`, and `sdk/`. Experiments stay under `research/`. Keep that split intact when reviewing patches.

See also [CONTRIBUTING.md](https://github.com/udinmoInc/antech-kdf/blob/main/CONTRIBUTING.md) and [CODE_OF_CONDUCT.md](https://github.com/udinmoInc/antech-kdf/blob/main/CODE_OF_CONDUCT.md) in the repository.

## Production checks

```bash
cargo check --workspace
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

## Research workspace

```bash
cargo check --manifest-path research/code/Cargo.toml --workspace
```

## Contribution habits

- Prefer small, reviewable PRs with clear crypto/API impact notes
- Update conformance vectors when digests intentionally change
- Do not add production → research Cargo dependencies
- Keep public docs focused on the product and review materials, not internal workflow

<Note>
Do not change digest behavior, v2 encoding, or public API semantics unless the change is intentional, versioned, and covered by updated vectors.
</Note>

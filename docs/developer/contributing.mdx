Production work lands under `crates/`, `bindings/`, and `sdk/`. Experiments stay under `research/`. Keep that split intact when reviewing patches.

## Production checks

```bash
cargo check --workspace
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

## Research workspace

```bash
cargo check --manifest-path research/code/Cargo.toml --workspace
```

## Contribution habits

- Prefer small, reviewable PRs with clear crypto/API impact notes
- Update conformance vectors when digests intentionally change
- Do not add production → research Cargo dependencies
- Keep MDX docs free of repository-process boilerplate — document the product, not the docs toolchain

<Note>
Do not change digest behavior, v2 encoding, or public API semantics unless the change is intentional, versioned, and covered by updated vectors.
</Note>
